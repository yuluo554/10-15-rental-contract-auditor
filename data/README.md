## 2. 数据源可获取性记录

- **可获取**：最高法官网、北京人大法规库、上海市政府官网、北京住建委官网均为静态 HTML，可程序化实抓，满足"原文逐字锚点"纪律（查证记录 #1-#4）。
- **不可获取（阻断）**：flk.npc.gov.cn 为 JS 渲染 SPA，程序化直连实测不可行（查证记录 #5）。因此本项目**不接入 flk 作为数据底座**；如未来需扩源，须先完成该源的原文直连查证，遵守"未挂原文核对不得落库"纪律。
- **开源空白软论据**：GitHub 检索式 `"租房 合同 审查"`，检索基准日 2026-10-14，仅零星个人 demo（≤4 星），未见"租客视角+城市数值规则包+法条锚点"成体系开源。此为软论据（⬜），复跑检索式即可核验。

## 3. 合成数据纪律

本项目全部测试样例为**合成合同**，必须遵守：

1. **假姓名**：使用明显虚构的姓名（如"张三""李四"式样例名），不得使用可识别真实个人的姓名组合。
2. **假手机号**：一律使用白名单号段 **`19900000000` 号段**（如 19900000001、19900000002…），不使用其他号段。
3. **假身份证**：如样例需要身份证号字段，使用格式合规的虚构号码，不使用任何真实号码。
4. **不植入真实个人信息**：禁止从任何真实合同/泄露数据中复制内容进入样例集。
5. **植入真值显式登记**：每个合成样例的元数据必须登记"应命中哪些规则、应判定为何"（`expect` / `also_expect`），**以及要素抽取的字段真值**（`expect_fields`：应有值的字段 → 期望取值；`expect_absent_fields`：应观测不到的字段）。后者是 B1 算**字段级 P/R/F1** 的独立来源——缺了它 B1 只能退化成布尔式准确率。
6. **每形态都要有采样件**：规则的每个 `check_type` 形态都须有 ≥1 份样例提供真值，并在规则包 `coverage.truth_sampling` 登记采样数（分子）与采样清单；**有规则却零采样件 → 基准判未达标**。
7. **覆盖易错形态**：样例集须显式覆盖"`skipped` 不冤枉用户 / 无条件义务缺失 = noncompliant / 无适用项 → not_assessed"三类形态（plan/04 §7）。

## 4. 数值口径纪律

- 数值口径**一处定义**（规则包条目），**多处引用**（引擎、报告、文档）。
- 题面与文档引用的条款号仅限上表已核对清单，不得凭印象新增。
- 规则包每条数值规则须携带：来源文件、条款号、法条原文逐字引用、查证状态（✅/⬜）；缺锚点规则不得被引擎加载生效。
