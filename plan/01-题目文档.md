# 题目文档：房屋租赁合同审计器（租客视角）

> **项目性质**：不参赛项目题（发布 GitHub 公开仓库，署名 yuluo554）
> **目标产出**：`10-15-rental-contract-auditor`（房屋租赁合同审计器·租客视角）
> **版本史**：v1（2026-10-14 定稿）
>
> **定位宣言**：租客不是律师——把分散在民法典与城市条例里的数值规则做成可核验的合同体检，每条判定挂法条原文锚点，这是 LLM 聊天给不了的持久规则库 + 可复现判定。

---

## 1. 介绍

### 1.1 痛点

租房合同是大多数普通人一生中签署次数最多的法律文本之一，但租客面对它时几乎处于完全的信息不对称：

- **规则分散**：押金上限、租金收取上限、备案期限、退还期限这些"硬数字"规则，分散在《中华人民共和国民法典》租赁编与各城市地方性法规之中。例如北京市的押金规则在《北京市住房租赁条例》（2022-09-01 施行），上海市的对应规则在《上海市住房租赁条例》（2023-02-01 施行），两地的押金托管、租金监管、罚则条款实质不同。
- **LLM 聊天不可持久**：向通用大模型"问一句"，得到的回答没有挂靠到可核验的法条原文，没有版本化的规则口径，也没有可复现的判定过程——下一次问、换一个模型问，答案可能漂移。
- **模板合同有陷阱空间**：格式合同中可能出现超出法定上限的押金要求、超长期限、模糊的退还期限等条款，租客缺乏逐条比对的工具。

### 1.2 开源空白

- **商业侧**：幂律智能、法大大等面向企业合同审查，不覆盖"租客视角 + 城市数值规则包"场景。
- **开源侧**：GitHub 检索式 `"租房 合同 审查"`（检索基准日 2026-10-14）仅见零星个人 demo（≤4 星），未见"租客视角 + 城市数值规则包 + 法条原文锚点"成体系的开源项目（⬜ 软论据，依检索式与基准日记录于 `data/README.md`）。

### 1.3 方法论文文脉

本题遵循"条款库 + versioned ruleset（本题为**城市差异包**）+ 合成数据植入真值 + 内置基准 + 离线交付（PySide6 桌面 exe + CLI），纯本地零上传"的方法论文脉，与同系列合规审计类项目一脉相承。

## 2. 任务要求

首期限定 **5 个模块**，逐个交付，每个模块遵守统一确定性纪律：**任何规则数值、判定依据，未挂法条原文核对不得落库、不得生效、不得进入计算路径。**

### 模块 ①：合同文本导入与条款切分

- **输入**：租客粘贴或导入的租赁合同纯文本。
- **输出**：结构化条款序列（条款号 + 条款文本 + 类型标签），作为后续判定的定位基础。
- **确定性纪律**：切分结果中的条款号必须能在原文中定位到逐字原文；无法定位的切分必须显式标注为"待人工确认"，不得静默吞掉。

### 模块 ②：城市规则包加载（京 / 沪两包）

- **输入**：城市标识（北京 / 上海）。
- **输出**：该城市的 versioned ruleset——押金上限、租金收取上限、备案期限、退还期限、罚则等数值规则及其法条原文锚点。
- **确定性纪律**：规则包中每条数值规则必须携带来源文件、条款号、法条原文逐字引用与查证状态（✅/⬜）；缺锚点的规则不得被引擎加载生效。
- **扩展项**：其他城市条例包（素材逐一查证后方可入包）。

### 模块 ③：数值规则判定引擎

- **输入**：模块①的条款序列 + 模块②的城市规则包。
- **输出**：逐条判定结果（符合 / 不符合 / 缺失 / 无法判定），覆盖押金上限、租金收取上限、租期上限（民法典第 705 条：租赁期限不得超过二十年）、备案期限、押金退还期限等数值规则，以及合同要素完整性等定性检查项（民法典第 704 条）。
- **确定性纪律**：判定输出必须回指规则包中的锚点 ID 与原文；同一输入在同一规则包版本下判定结果必须可复现（同版本 + 同输入 = 同输出）。

### 模块 ④：风险报告输出

- **输入**：模块③的判定结果集。
- **输出**：体检报告——每条判定附：条款号锚点、法条原文引用、来源文件（文号/施行日期/URL）、判定理由；导出为可存档的报告文件。
- **确定性纪律**：报告中不得出现报告生成逻辑自行编造的法条原文；所有原文必须来自规则包已核对语料。

### 模块 ⑤：合成合同测试样例与内置基准

- **输入**：合成合同样例生成配置（假姓名、假手机号，见 `data/README.md` 数据纪律）。
- **输出**：植入已知风险点的合成合同样例集 + 内置基准（基准口径与门槛来源记录在案，题面不写会漂移的硬数字）；基准随项目发布，任何人可一键复跑。
- **确定性纪律**：每个样例的"植入真值"（应命中哪些规则、应判定为何）必须在样例元数据中显式登记，与判定引擎输出自动比对。

### 扩展项（非首期门槛）

- 其他城市条例包（须先完成该条例的原文直连查证）。
- Word 文档回写（在合同文本上直接标注修改建议）。

## 6. 边界与非目标

### 6.1 法律意见免责红线

本项目输出为**辅助参考的合同体检结果，不构成法律意见**。所有报告页面与导出文件必须携带免责声明；不得使用"律师审查""法律效力的结论"等表述。

### 6.2 隐私红线

- **纯本地零上传**：不做任何网络请求上传合同内容；桌面端与 CLI 均离线可用。
- **合成数据纪律**：测试样例一律使用假姓名、假手机号（白名单号段，如 `19900000000` 号段），不使用真实个人信息；详见 `data/README.md`。

### 6.3 品牌隔离

本项目不提及任何姊妹项目，独立署名与独立定位陈述。

### 6.4 首期范围限定

- 首期仅京/沪两城市规则包；其他城市属扩展项，素材逐一查证后方可入包。
- 首期不接入在线法规数据库实时更新（flk.npc.gov.cn 已实测程序化直连不可行，见 `data/README.md`）。
- 首期不做 Word 回写（扩展项）。
- 题面不写会漂移的硬数字（测试样例数、基准用例数等），只写指标口径与门槛来源；数值口径一处定义、多处引用。
