# 04 - 基准与评测：口径、门槛来源、可证伪探活

> 对应题面模块⑤与评分维度"功能效果 40 分"。本文件定义"怎么证明判定引擎对、门槛从哪来"。

---

## 1. 评测三件套（全部零 API 依赖、可离线复跑）

| 套件 | 名称 | 驱动方式 | 证明什么 |
|---|---|---|---|
| B1 | 解析基准 | 样本驱动（合成样例真值） | 要素抽取**字段级 P/R/F1** |
| B2 | 端到端判定基准 | 样本驱动（植入真值对账） | 判定状态命中率 / 误报率 |
| B3 | 规则驱动边界扫描 | **规则驱动**（不读真值库） | 引擎在**所有有限端点**上对 |

**B1 的 P/R/F1 是真算的**（M4 落地）：真值侧逐样例登记"应有值的字段 → 期望取值"
（`expect_fields`）与"应观测不到的字段"（`expect_absent_fields`），由生成器按合同入参
**独立推导**，不调用引擎抽取函数——否则引擎抽错时期望跟着一起错，探活永远绿。
TP = 期望有值且引擎取到**同一取值**；FP = 期望 absent 却抽到值，或取值不符；
FN = 期望有值却抽不到；分母 = TP + FP + FN。

**B2 的分母是真值登记的每条规则**（`expect ∪ also_expect`）：只算"非 pass 集合"会漏掉
一整类错误——真值登记 `compliant` / `skipped` / `reference`、观测却是别的 pass 侧状态时，
两侧都不在非 pass 集合里，**恒不报**（`also_expect` 会沦为"登记了但从不校验"的死数据）。

**为什么必须分两层**：样本驱动证明"引擎在这些样本上对"，但**样本没覆盖的端点它证明不了**。规则驱动层从规则表推导切换端点、做 ±精度邻域断言，专门补这个缺口。判别 = "这个基准的分母，是否依赖真值库恰好覆盖了某个端点？"依赖就是样本驱动，必须补一条规则驱动的。

## 2. 合成样例与植入真值

### 2.1 生成器

`tools/gen_samples.py` 产出 `data/samples/*.json`（合成合同 + 植入真值），固定 seed 可复现。

- **禁用 stdlib `random`**：自研确定性 RNG（splitmix64），stdlib random 不承诺跨版本序列一致。
- **禁 set 迭代序、禁系统时钟**：落盘产物无时间戳，两次运行逐字节一致。
- 产物整体作为**字节冻结 fixtures 入仓**，配 `--check` 位级一致守门（`SAMPLES_FROZEN_OK`）。

### 2.2 样例元数据结构

```jsonc
{
  "sample_id": "S-BJ-001",
  "city": "北京",
  "party": "enterprise",
  "lease_kind": "ordinary",         // ordinary | affordable（M1 新增维度，见 plan/02 §5.2）
  "contract_text": "...",           // 合成合同全文（假姓名/假手机号）
  "expect": {
    "CN-LEASE-TERM-MAX": "compliant",       // 主期望
    "BJ-DEPOSIT-MAX-1M": "noncompliant"
  },
  "also_expect": { "BJ-RENT-INTERVENTION": "reference" },  // 同一植入隐含的其余结论
  "notes": "押金 2 个月租金，超北京上限 1 个月"
}
```

**真值语义定一次**：`expect` 记主期望，`also_expect` 记同一注入隐含的其余结论（如 quota 条进"条件触发栏"的 `reference`）。对账语义收成单一实现源（`benchmark/cases.py`）：`compare_nonpass` 管误报/漏报（非 pass 集合口径），`compare_exact` 管**全量精确对账**（`expect ∪ also_expect` 每条都要核——非 pass 口径会漏掉"两侧都在 pass 侧"的状态不符）。

### 2.3 覆盖抽样双登记

真值库对规则各形态（数值上限/期限义务/定性要素/条件触发）**各有覆盖件仍不够**——manifest 必须逐形态登记 **"规则包条目总数（分母）/ 真值库采样数（分子）/ 采样清单"**，并声明"抽样覆盖、非逐条穷举"。判别 = "这个覆盖声明里，分母（总数）和分子（采样数）都写出来了吗？"只写分母就是假覆盖。

**落地形态**（M4，`src/rca/benchmark/coverage.py` 单一实现源）：

```jsonc
"coverage": {
  "note": "…",
  "sampling_declaration": "抽样覆盖、非逐条穷举",
  "rule_totals_by_check_type": { "numeric_limit": 4, "deadline_obligation": 3, … },
  "rule_total": 10,
  "truth_sampling": {
    "numeric_limit": {
      "rule_total": 4,             // 分母
      "sampled_rules": 4,          // 分子
      "sampled_rule_ids": ["BJ-DEPOSIT-MAX-1M", …],  // 采样清单
      "sample_ids": ["S-BJ-001", …]
    }, …
  },
  "truth_sampled_total": 10
}
```

三件套由生成器实算写入规则包，基准层核对"登记的数 == 实算的数"，CLI（`rules --city X`）
与导出报告都展示。**某形态有规则却零采样件 → 基准判未达标**（分子为 0 的形态等于没测）。

## 3. 验收门槛是数据不是代码

门槛（达成率下限 / 误报率上限 / 运行时长上限）随**规则包 manifest** 下发，基准层**只读**；缺失即报配置错误（退出码 2），**不得回落代码里的默认值**——门槛内联在引擎里就是"抄进代码的第二份真相"。

manifest 门槛段示例：

```jsonc
"benchmark_thresholds": {
  "B1_parse_f1_min": 0.95,
  "B2_hit_rate_min": 0.95,
  "B2_false_positive_max": 0,
  "B3_boundary_pass_rate_min": 1.0,
  "max_runtime_seconds": 60
}
```

## 4. 退出码三语义（锁进测试）

| 退出码 | 语义 |
|---|---|
| 0 | 全部已测套件达标 |
| 1 | 未达标 或 门控拦截 |
| 2 | 用法错误 / 未知名 / 配置错误 |

`--only <suite>` 传未知名必须走 exit 2（否则"跑了个不存在的基准"会被读成成功）。`--suite` 部分运行时不判定未测指标（否则 `bench --suite B1` 会把"没测"误报成"未达标"，把"未知"当"失败"）。

## 5. 可证伪探活（每套件配一个，防"基准什么都没查"）

给每套件注入一个缺陷，**断言 `run_benchmarks()` 真的返回非 0**（端到端，不是只断言对账函数返回非空——对账函数对、门槛判定通路没接上的话，只断言函数层照样绿）：

| 套件 | 注入的缺陷 | 期望 |
|---|---|---|
| B1 | 系统性篡改样例的字段期望取值 | 基准报未达标（F1 跌破门槛） |
| B2 | 注入一条必然误报的规则（坏引用） | 基准报未达标（未登记/误报） |
| B3 | 把规则表某边界值改 ±1 | 基准报未达标（独立真值来源抓到） |

**注入强度必须越过门槛**：门槛是 0.95，只改一条样例的一处期望仍在容差内——此时基准判"达标"是**正确**的，那种注入证明不了门槛通路是活的。故 B1 探活系统性改错同一字段的全部样例。

**探活的隐含前提 = 期望必须有独立来源**：期望值与引擎**同源**（都读现行规则包）时，注入缺陷两边一起变、探活永远绿。B3 的期望锚定**冻结真值/独立公式推导**，B1 的期望锚定生成器入参（不调引擎抽取函数），都不与引擎共用通路。

**未启用套件不冒充通过**：误报对照零样本时 `hits(0) <= max(0)` 恒真、一致率恒 1.0——"没查"被读成"查了没问题"。空分母分支统一 `not_enabled=true` + notes 写明"该类用例未生成" + **exit 1**。判别口诀：**每个"达标"分支先问"分母为 0 时它会怎样？"——恒真就是假门。** 同理，**某形态有规则却零采样件（分子为 0）也判未达标**。

## 6. 规则驱动边界扫描（B3 详设）

从规则表本身推导全部有限边界，取 `±0.01`（判定精度）邻域断言级次切换：

- 押金上限：`deposit_months` 在 `1.00` 邻域 → `1.00` compliant / `1.01` noncompliant
- 租金收取上限：`rent_prepay_months` 在 `3.00` 邻域同理
- 租期上限：`lease_term_years` 在 `20` 邻域 → `20` compliant / `20.01` noncompliant
- 备案期限：`filing_days` 在 `30` 邻域
- 退还期限：`deposit_refund_days` 在 `3`（工作日）邻域

**双向对账**：规则表推导端点 vs 独立实现（直接读规则包的 `op`/`value` 做算术断言）——两条路径互验，避免"同一段代码自己测自己"。

**精度死区显式建模**：月→年换算用两位小数（`ROUND_HALF_UP`），租期边界断言从**实际跳档点**起算，不假设精确端点。

---

## 7. 判定语义对账（防假合规）

基准必须覆盖三类易错形态：

1. **`skipped` 不冤枉用户**：自然人合同对企业专属规则 → 期望 `skipped`，不是 `noncompliant`。
2. **无条件义务缺失 = `noncompliant`**：合同缺民法典 704 条某要素 → 期望 `noncompliant`，**不是 `skipped`**（防"没做"记成"不用做"）。
3. **无适用项 → `not_assessed`**：一条规则都不适用的样例 → 整体 `not_assessed`，**不输出 `compliant`**。

## 9. 既定口径清单（动了会打挂基准的约定）

以下约定变更必须同步改"引擎 + 真值库 + 基准 + 文档"四处，并登记决策记录：

- **K1** 真值语义：`expect` 主期望 + `also_expect` 隐含结论；对账语义两件：`compare_nonpass`（误报/漏报，非 pass 集合口径）+ `compare_exact`（全量精确对账，`expect ∪ also_expect` 每条都核）。
- **K2** 判定状态五值与 `effect` 枚举的取值集合。
- **K3** 门槛数值来源 = 规则包 manifest（非代码）。
- **K4** `effective_ruleset(city, scope)` 签名与作用域集合 `{calc, check, quota}`。
- **K5** 精度约定：金额/月数两位小数 `ROUND_HALF_UP`；租期年数两位小数。
- **K6** 测试全离线、零 API 依赖。
- **K7** CLI 退出码四语义（0/1/2/3）。
- **K8** 合成数据假名/假号段纪律（`19900000000` 号段）。
- **K28**（M4 新增）**覆盖登记三件套**：分母（`rule_totals_by_check_type` / `rule_total`）+ 分子（`truth_sampling.<form>.sampled_rules`）+ 采样清单（`sampled_rule_ids` / `sample_ids`）+ 声明（`sampling_declaration`），由 `benchmark/coverage.py` 单一实现源实算。改则须同步生成器、基准核对、CLI 输出、报告覆盖章节。
- **K29**（M4 新增）**B1 真值侧字段登记**：`expect_fields`（应有值字段 → 期望取值）+ `expect_absent_fields`；期望由生成器按合同入参独立推导，**不得调用引擎抽取/量化函数**。改则 B1 的 P/R/F1 失去独立来源（探活假绿）。
- **K30**（M4 新增）**B2 分母 = 真值登记每条规则**（`expect ∪ also_expect`）。退回"只算非 pass 集合"会让 `also_expect` 重新变成死数据（pass 侧状态不符恒不报）。
