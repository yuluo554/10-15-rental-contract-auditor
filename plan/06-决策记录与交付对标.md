| D4 | 2026-10-14 | **离线交付**：PySide6 桌面 exe + CLI 双入口 | Web 在线服务 | 隐私红线要求纯本地零上传；离线交付与"合同不上传"承诺一致 |
| D5 | 2026-10-15 | **首期不使用 LLM**（全链路确定性规则） | 接 LLM 做非结构化抽取兜底 | 本项目是纯确定性规则 + 结构化输入，正则可覆盖中文合同主要表述形态；零 LLM 则结论 100% 可复现、零 API 依赖、基准可离线跑、脱敏面无外部调用。扩展项保留 LLM 兜底通路（纪律预定义：只填"宁缺"槽位，绝不覆盖确定性抽取值） |
| D6 | 2026-10-15 | 报告**自写最小 OOXML writer**（XLSX），不引 openpyxl | 用 openpyxl 导出 XLSX | 第三方库 ZIP 元数据（宿主系统标识、时间戳）会让字节漂移，破坏"同输入同字节"承诺；自写 `ZIP_STORED` + 固定 `create_system`/`date_time` 零第三方依赖且逐字节确定 |
| D7 | 2026-10-15 | **双重门控拆分**：`status`（数值核对）与 `clause_status`（条款号核对）两个独立状态，只有数值 status 门控判定路径 | 耦合成单一 status | 耦合会让条款号核不到时把已核对数值也无谓阻断；或只看数值 status 时"悄悄当作已核对" |
| D8 | 2026-10-15 | **门控按作用域**（`calc`/`check`/`quota`）+ 第三态 `input_required` | "整包全 verified"当唯一门 | 一份规则包承载多用途参数时，与判定无关的 pending 会阻断整条判定路径；`input_required` 是"本不由规则包承载的外部输入"，放行但运行时必索（缺失 exit 2，绝不静默取 0/1） |
| D9 | 2026-10-15 | **`effect` 义务类型分栏**：`standing_obligation` / `periodic_obligation` / `conditional_institution` | 混在一个 `triggered` 布尔里输出 | "政府可以采取价格干预"是**监管裁量权**，不是相对人的无条件义务；混写会把监管裁量说成企业法定义务。结论分栏呈现，频次只取无条件义务栏 |
| D10 | 2026-10-15 | **判定状态五值**：`compliant`/`noncompliant`/`skipped`/`unknown`/`not_assessed` | 三态（符合/不符合/不适用） | 三态无法表达"没看到"（`unknown`）与"没检查过"（`not_assessed`）；"没查出问题"与"没检查过"必须可区分（判定类工具最易被攻击的假合规点） |
| D11 | 2026-10-15 | `skipped` **只给原文明确写了适用情形的项** | 缺材料也判 `skipped` | 反向陷阱：把"应尽而未尽的义务"判成 `skipped` = 把"没做"记成"不用做"，合规结论虚高。判据 = "这项义务有没有前提条件？"原文"应当 X"（无条件）→ 缺 X 记 `noncompliant` |
| D12 | 2026-10-15 | **CI 矩阵裁剪**：`windows×{3.8,3.12}` + `ubuntu×{3.12}` | 四矩阵（含 ubuntu×3.8） | ubuntu 新镜像对 py3.8 支持存疑；旧解释器只在 windows 守，跑完按实况记录，不硬凑四矩阵 |
