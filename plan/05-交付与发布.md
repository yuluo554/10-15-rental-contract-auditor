# 05 - 交付与发布：打包、CI、发布留档

> 对应题面提交材料 5/6/8 与评分维度"应用完整性 20 分"。本文件定义"怎么交付、怎么发布"。

---

## 1. 交付形态

| 形态 | 载体 | 说明 |
|---|---|---|
| CLI | `rca` 命令 | 合同体检入口：`check` / `scan` / `report` / `rules` / `bench` |
| 桌面 exe | PySide6 onedir 双 exe | GUI（`console=False`）+ CLI 控制台（`console=True`，无 Python 机器上的脚本化验证通路） |
| 报告 | Markdown + XLSX | 人读 + 机读双轨，均逐字节可复现、无外链 |

**纯本地零上传**（题面 §6.2 隐私红线）：桌面端与 CLI 均离线可用，不做任何网络请求上传合同内容。由测试断言"源码无出网调用"。

## 2. 依赖分层（extras）

```toml
[project.optional-dependencies]
gui     = ["PySide6>=6.6"]           # 桌面 GUI（floor 3.12，无需为老解释器钉上限）
report  = []                          # 自写 OOXML writer，零第三方依赖
dev     = ["pytest>=7,<9", "pyyaml>=6"]
build   = ["pyinstaller>=6", "setuptools<81"]
```

**纪律**：

- **测试面 = 安装面**：测试套件真 import 的每个库都必须在 README 快速开始那条安装命令的 extras 里。README 与 CI 装同一集合 `.[dev]`（自写 writer 使 report 无需 extra）。
- **extras 一律不进运行时必需面**：核心层零第三方依赖（纯 stdlib），`pip install -e .` 即可跑 CLI。
- **PyInstaller 版本按"打什么"分档**：打 GUI（PySide6）**必须 ≥6**（5.x 确定性崩在 `Instruction object is not iterable`）；只打 CLI 的老解释器可 5.x。本机 3.12 装 6.22.3 → **发布构建固定用 `py -3.12`**。
- **打包工具前置依赖钉进 build extra**：`setuptools<81`（PyInstaller 5.x import `pkg_resources`，setuptools 81 起移除），配守门测试断言该钉法。

## 3. CI 矩阵

```yaml
strategy:
  matrix:
    os: [windows-latest, ubuntu-latest]
    python-version: ["3.12"]     # floor >=3.12（3.8/3.9 已 EOL、3.10 到期）
```

四 job：`test`（windows×3.12 + ubuntu×3.12）+ `install-smoke`（windows×3.12，
**非 editable 安装**冒烟）+ `package`（windows×3.12，真构建 + 产物级验收）。

> **`install-smoke` 的由来（D1，2026-10-20）**：此前全部 job 都走 `pip install -e`，
> 而数据在包外 → `pip install <wheel>` 后 `rca rules` 直接 exit 2，本地与 CI 却全绿。
> 该 job 走"建 wheel → 全新 venv → 装 → 中立目录跑"，断言规则条数 / `BENCH_OK` / `check` 退出码。

**CI 必配（开发期前置，不留给发布期救火）**：

- `env: PYTHONUTF8: "1"` + `PYTHONIOENCODING: utf-8`（覆盖所有 job 步骤）
- `actions/checkout` 配 **`fetch-depth: 0`**（脱敏审计的历史扫描依赖全量历史，浅克隆会静默削弱成空验）；配守门测试断言每个 checkout step 的 `fetch-depth == 0`
- 装 `-e ".[dev,gui]"`（**不是** core-only——pytest 与 PySide6 都是测试期真 import 的库）
- Linux job 若跑 GUI 测试：`sudo apt-get install -y libegl1 libgl1 libxkbcommon0 libdbus-1-3 libfontconfig1`（PySide6 在裸 runner 上缺 `libEGL.so.1` 直接 ImportError，offscreen 平台同样要加载）

**诚实口径**：未推送 = 未跑 CI。M0–M5 的 DoD 一律写"**本地等价校验**"并注明"未接远端，CI 待首推验证"；M6 首推后据实补记真实 run id 与结论。

## 4. 编码三层加固（windows 全挂 + ubuntu 全过 = 编码类签名）

| 层 | 手段 | 救谁 |
|---|---|---|
| CI 全局 | `env: PYTHONUTF8=1` + `PYTHONIOENCODING=utf-8` | CI 全部步骤 |
| 代码入口 | `_ensure_utf8_stdio()`（按 `stream.encoding` 探针 reconfigure） | 真实用户机器 |
| 子进程解码 | `subprocess.run(..., encoding="utf-8", errors="replace")` | 一切环境（**无环境变量可替代**） |

**覆盖范围 = 所有会打印的可执行入口**，含 `tools/` 下每个脚本（不只主 CLI）。配回归测试：以 cp1252 环境真跑一遍（本机即可复现）。

## 5. 字节冻结分层设防

| 层 | 手段 | 守门 |
|---|---|---|
| 文本行尾 | `.gitattributes` `* text=auto eol=lf` | 冻结 fixtures 出现 CR 即大声失败 |
| 官方快照 | `.gitattributes` 标 `-text`（`*.txt` 快照 + `*.pdf binary`） | 检出后重算 sha256 与台账比对 |
| zip 容器 | 生成器一律 `ZIP_STORED` + `create_system=0` + 固定 `date_time` | "任意平台重生成位级一致" |
| 生成器写盘 | `write_bytes` 或 `newline="\n"`（**不要用 `write_text` 默认**，会把 `\n` 翻成 `\r\n`） | EOL 守门会持续抓"自己人" |

## 6. 打包（PySide6 onedir 双 exe）

- **spec datas 白名单单一事实源**：只由 `rca.packaging.build_datas()` 产生；禁区段（如未来含版权原文的 `raw/` 子集）在构建器内直接抛错 + spec 文本守门测试。
- **构建后三断言**（任一违反 exit 1）：dist 全树禁区扫描（只匹配 **dist 顶层**，防依赖包自带同名子目录误伤）+ 内嵌数据逐份 sha256 对账 + 白名单外多余检测。
- **`find_data_dir` 冻结分支**：显式 > 环境变量 > `sys._MEIPASS/data`（PyInstaller 6）→ exe目录/_internal/data（PyInstaller 5 兼容）> CWD 上溯，配分支测试锁死。
- **冻结态自检断言数据目录落在 exe 目录内**：`os.path.commonpath([exe 目录, data 目录]) == exe 目录`；**非冻结态该项返回 None 而非 FAIL**。判别 = "这个自检项在只有 exe 的机器上还成立吗？"
- **`--selftest <输出文件>`**：窗口版 stdout 不接终端，这是唯一能脚本化验收窗口 exe 的通路。自检 JSON 断言 `frozen=true` + `data_dir` 落在 dist 内 + 规则数 > 0。
- **干净验证在中立目录**（`%LOCALAPPDATA%\Temp` + `env -i` 剥离 PATH），**别在仓库树内跑**（CWD 上溯会命中仓库 data，"内嵌数据"验了个寂寞）。
- **降级提示按 `is_frozen()` 分流**：冻结态说"本发行包未内嵌该功能"，源码态才说 pip 安装。

## 7. GUI 分层与静态门禁

- **GUI 只消费引擎 API、零判定逻辑**，靠 **AST 静态门禁**守住，三条齐上：
  1. 不 import 规则层（唯一入口 `engine/pipeline.py`）
  2. 无算术运算（`BinOp` 且两侧操作数均非字符串字面量的 `*` `/` `-` `//` `%` `**`）
  3. 无政策数值字面量（与引擎侧同一份 `BANNED_TOKENS`）
- **`rca gui` 惰性导入**：`try` 包住**从 import 到调用完成**的整段（不是只包 import 行），`except ImportError` 兜底 exit 3。回归用 `builtins.__import__` 打桩断言 exit 3 而非裸异常。
- **编排上收**：`engine/pipeline.py` 公开函数组（`build_card` / `check_contract` / `build_report`），CLI 与 GUI 共用。测试断言**行为等价**（三方对账：CLI stdout == pipeline 直调 == 报告章节），而非"都调了同一个函数"这种字面声明。

## 8. 脱敏审计（四步 + 产物扫描，固化成入仓脚本）

`tools/audit_desensitize.py`，四模式：`selftest`（阳性/阴性对照）/ `tracked` / `history` / `messages`。

1. `git ls-files | grep -iE "\.env$|\.key$|secret|token"` 应为空；`.gitignore` 覆盖 .env/运行产物/个人材料/`data/**/_private/`
2. **内容级扫描**全部跟踪文本文件：密钥、手机号 `1[3-9]\d{9}`、身份证、个人路径、内网 IP、邮箱
3. **二进制样例单独扫**（git grep 跳过二进制）
4. **提交元数据邮箱**：`git log --format="%ae %ce" --all | sort -u` —— 本机实测是**真实 QQ 邮箱**（8 个提交全部中招），发布前须改写为 GitHub noreply（`<id>+<user>@users.noreply.github.com`，id=282769740）
5. **构建产物本体扫描**：全 dist 树 Python 字节读法跑强标记；命中串豁免裁决 = 官方原件同串比对

**扫描器纪律**：

- **token 运行时实算**：邮箱数字串从 `git log --format=%ae` 实算、用户名从 `getpass.getuser()` 实算、盘符从仓库绝对路径实算；源码与留档**零词面**。每次运行首行打印 token provenance。
- **命中分级**：HARD（exit 1）/ REVIEW（人工豁免留档）/ advisory（只报不阻断）；行内 `audit-allow` 放行标记（仍打印）。
- **豁免项进阴性对照**：`*@users.noreply.github.com` 与 `git@github.com`（传输地址）不是个人邮箱；sha256 hex 串不是手机号（加 hex 边界环视）。
- **排除项按对象类型不按名字**（路径 glob + 规则名）。
- **审计输出一律掩码化**——留档会引用输出，输出本身不得成为二次泄漏源。
- **历史扫描配机制探活断言**（先搜必然存在的串如仓库名，搜不到即硬失败），防多 rev 静默空扫假绿。
- **个人标记按组合路径签名**匹配（`Users\<名>`/`ProgramData\<工作根>`），不匹配裸词（防 Qt DLL 内嵌 `ASUSTek` 含 "ASUS" 误报）。

**发布前窗口**：本机 git 全局 `user.email` 是真实 QQ 邮箱 → 首推前（无远端、零消费者）用 `git filter-repo --email-callback` 改写，**所有历史重写在"还没人看见"时做完**。

## 9. 发布流程（M6）

1. **建仓**：`gh repo create yuluo554/10-15-rental-contract-auditor --public --description "…" --source . --remote origin`（**不带 `--push`**）→ 验证 SSH key → `git remote set-url origin git@github.com:yuluo554/10-15-rental-contract-auditor.git`（token 缺 `workflow` scope 时 HTTPS push 会被拒，SSH 不受限）→ push
2. **CI 首跑**：预算"诊断+修复+再推一轮"（首跑 = 全项目首次 CI，环境差异型问题集中爆发；首跑红不等于方法论失败，修完即绿就是预算内正常消耗）
3. **CI 对账**：`gh run list` 与 push 事件逐条配对（push 事件数 = run 数，**不是提交数**；amend/force push 后旧 run 的 sha 已不可达要注明）
4. **收尾固化**：`git tag -a v0.1.0` + push tag + `gh release create`（notes 用 `--notes-file` 传文件；**发布附件名一律 ASCII**，gh 在 Git Bash 下会剥中文附件名）
5. **发布 zip 打包确定性**：`ZIP_STORED` + 条目显式 sort + 固定 `date_time`，两次独立打包逐字节一致（留档写明"可复跑的是同 dist→同 zip 这步，exe 构建不承诺跨机字节一致"）
6. **发布物本体已验**：真下载 release 附件 → 下载件 sha256 与留档一致 → 解压中立目录跑 `--selftest` 通过
7. **README 状态行转正** + CI 徽章 + topics（`gh repo edit --add-topic`，加完 `gh api` 回读确认）

**对外动作分级授权**：普通开发流 push 无需授权；tag/release/topics 需用户在对话中确认一次（多项收拢一次 AskUserQuestion，各带推荐默认）；visibility/删仓/历史重写必须用户明确授权。

## 10. 发布留档三件套

| 文档 | 内容 |
|---|---|
| `plan/RELEASE-M6.md` | 脱敏四步命令与结论 / 干净环境验证逐条退出码 / CI 对账表 / 发布物 sha256 / 拍板留档 |
| `plan/HANDOFF-M6.md` | 发布期跨对话续接快照 |
| `plan/DIST-sha256-M6.txt` | 产物 sha256（由 `sha256sum`/`hashlib` 输出直接重定向生成，**人只写注释行**，防手工转录错位） |

**留档诚实纪律**：

- 确认类条目只能在用户实际确认后打勾，**禁止预填"用户已确认"**；未获答复按推荐默认执行时如实写"未获明确答复，按推荐默认执行"。
- 未跑的项留 ⬜ 并说明原因，不留空不预填。
- 留档文档本身用**描述性指代**（"旧邮箱本地片段"/"本地工作根签名"），不复述敏感字面值——否则"全历史 0 命中"验证永远过不了。
- **收官期新增文档先 `git add` 再跑本地审计**（tracked 扫描面只含已跟踪文件，"本地绿"≠未 add 的新文档干净）。
