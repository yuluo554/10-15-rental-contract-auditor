## 2. 官方快照入仓纪律

### 2.1 目录与命名

```
data/knowledge/raw/
  cn-civil-code.txt      # 民法典（最高法官网全文快照，UTF-8 文本）
  bj-housing-rental.txt  # 北京市住房租赁条例
  sh-housing-rental.txt  # 上海市住房租赁条例
  bj-deposit-escrow.txt  # 北京市押金托管与租金监管暂行办法
data/knowledge/MANIFEST.json   # 快照台账：来源 URL / 抓取日 / sha256 / 字节数 / 汉字数
```

### 2.2 三条硬纪律

1. **快照与 HTML 同批**：快照由 `tools/fetch_sources.py` 从官方 URL 抓取并就地剥离标签产出；抓取脚本**不重写正文**（只做标签剥离与空白归一），产物入仓后**禁手改**。
2. **`.gitattributes` 标 `-text`**：快照是被台账登记过 sha256 的字节冻结件，必须标 `-text`（连同 `*.pdf binary`），否则克隆时 EOL 归一化会让 sha256 失配。验证手段 = 检出后重算 sha256 与 `MANIFEST.json` 比对（`git status` 看不出来）。
3. **逐字比对锚**：任何规则条目的 `quote` 字段必须**逐字出现在对应快照中**——由生成器 `gen_rulesets.py` 在生成时断言（`assert quote in snapshot_text`），断言失败即生成失败。这是"机器化逐字比对"，取代人工核对。

### 2.3 快照再生成守门

`tools/fetch_sources.py --check` 重抓并逐字节比对入库快照，输出 `SOURCES_FROZEN_OK`；不一致即退出 1。**注意**：官方站点正文若在两次抓取之间被编辑（罕见但可能），`--check` 会如实报红，处置是人工确认后更新 `MANIFEST.json` 与规则包引用，**不静默放宽**。

## 3. 规则包（versioned ruleset）格式

### 3.1 一等数据资产

规则包是**生成器冻结产物**：`tools/gen_rulesets.py` 从"单份来源表 + 数值表"产出 `data/rules/ruleset-<city>.json`。**禁手改**；改需求走生成器整目录重生成，配"再生成逐字节一致"守门测试（`gen_rulesets.py --check` → `RULESETS_FROZEN_OK`）。

### 3.2 文件结构

```jsonc
{
  "ruleset_id": "bj-2024.10",          // 城市 + 版本锚点
  "city": "北京",
  "city_code": "bj",
  "version": "2024.10",
  "generated_by": "tools/gen_rulesets.py",
  "sources": [
    {
      "source_id": "SRC-CN-CIVIL-CODE",
      "title": "《中华人民共和国民法典》",
      "doc_no": "主席令第四十五号",
      "effective_date": "2021-01-01",
      "url": "https://www.court.gov.cn/zixun/xiangqing/233181.html",
      "snapshot": "data/knowledge/raw/cn-civil-code.txt",
      "snapshot_sha256": "<64 hex>"
    }
  ],
  "rules": [
    {
      "rule_id": "CN-LEASE-TERM-MAX",
      "title": "租赁期限不得超过二十年",
      "check_type": "numeric_limit",
      "scope": "calc",                  // calc | quota | check（门控作用域，见 §4）
      "param": "lease_term_years",
      "op": "<=",
      "value": 20,
      "unit": "年",
      "applies_if": { "party": ["any"], "lease_kind": ["any"] },  // 见 §5.2
      "effect": "standing_obligation",  // 见 §5
      "severity": "high",
      "source_id": "SRC-CN-CIVIL-CODE",
      "clause": "第七百零五条",          // 缺锚点（clause/quote/source_id）即被加载侧拦下（§4）
      "quote": "租赁期限不得超过二十年。超过二十年的，超过部分无效。",
      "status": "verified",             // 数值核对状态：verified | pending
      "clause_status": "verified"       // 条款号核对状态：verified | pending
    }
  ]
}
```

### 3.3 字段语义（判定引擎只读这些字段，不读别的）

| 字段 | 语义 | 门控作用 |
|---|---|---|
| `check_type` | 判定类型分派键：`numeric_limit` / `deadline_obligation` / `element_completeness` / `text_prohibition` | 引擎按此分派 |
| `scope` | 计算路径作用域 | 门控按作用域取条目（§4） |
| `param` | 输入参数名（引擎从合同卡片按此取名） | — |
| `op` / `value` / `unit` | 数值判定三要素。`op` 取 `<=` / `<` / `>=` / `>` / `==`；**上限类**（`<=`/`<`）与**下限类**（`>=`/`>`）方向相反，引擎按 `op` 给出对应方向措辞（下限类判不符合时写"低于规则下限"，不写"超过上限"——把义务说反比措辞粗糙更糟） | 门控对象 |
| `applies_if` | 适用条件（`party` / `lease_kind`） | 不满足 → `skipped`（§5） |
| `effect` | 义务类型枚举 | 结论分栏（§5） |
| `severity` | 风险级：`high` / `medium` / `low` / `advisory` | 报告分级 |
| `quote` | 法条原文**逐字**引用 | 生成时对快照断言 |
| `status` | **数值**核对状态 | **唯一判定门控** |
| `clause_status` | **条款号**核对状态 | 只做可证性展示，不门控 |

### 3.4 版本号由台账**机器推导**（M3 补的硬纪律）

`version` 不是手写的第二份真相：由 `tools/gen_rulesets.py` 的 `derive_version()`
从**被本包规则引用的来源**中取**最晚的 `effective_date`**，形如 `YYYY.MM`。

- 取最晚施行日：包内任一规则所依据的来源更新，整套口径即随之变化。
- 月粒度：法规修订以月为发布节奏，日粒度会引入无意义的版本差异。
- 来源未在台账登记、或缺 `effective_date` → **显式报错**，不静默回落默认值。

为什么不能手写：版本号是"这套规则依据哪一版法规"的唯一标识。写死会与数据脱钩——
新增/替换一条规则所依据的来源后版本号还是旧的，报告标注的"依据版本"就指向了错的
原文版本，读者据此核证会核到错版本的法条。**可追溯 = 产物里看得见 + 能从台账复算**，
两者缺一不可（`rca check --json` 与报告都输出版本号；测试断言其等于台账推导值）。

## 4. 双重门控：数值门与条款门分开

一条规则有两类独立可核对的要素——**数值本身**（上限是多少）与**条款号/原文位置**（在第几条）。耦合成单一 status 会造成两个方向的失败：条款号核不到时把已核对的数值也无谓阻断；只看数值 status 时"悄悄当作已核对"。

**本项目口径**：

- `status`（数值核对状态）= **唯一门控**。`effective_ruleset(city, scope)` 拒绝任何 `status != "verified"` 的条目进入判定路径。
- `clause_status`（条款号核对状态）= 只进"可证性展示"，在报告的"未启用清单"里显式打印，不阻断判定。
- 两个状态**都在产物里显式可见**（报告附"规则启用状态表"）。

**锚点门（M1 补，题面模块②硬约束）**：除 `status` 外，加载侧还拦截**缺锚点**的条目——
`clause`（条款号）/ `quote`（法条原文逐字引用）/ `source_id`（来源）缺任一项即不生效，
并进"未启用清单"显式可见。理由：**"缺锚点的规则不得被引擎加载生效"不能只靠生成器单点保障**——
规则包可被手工替换、也可由第三方扩展包提供。缺锚点的判定会给出一条"看起来有依据"的结论，
读者却找不到原文核对，**比不判定更危险**。注意锚点门与 `clause_status` 不冲突：
前者查"锚点**是否存在**"，后者记"锚点**是否已人工核对**"。

### 4.1 门控按计算路径分作用域

一份规则包承载多种用途的参数，若用"整包全 verified"当唯一门，会让与判定无关的 pending 阻断整条判定路径。本项目三个作用域：

| scope | 含义 | 引用它的通路 |
|---|---|---|
| `calc` | 数值判定（押金上限、租金上限、租期上限） | `rca check` / GUI 判定页 |
| `check` | 定性检查项（合同要素完整性、禁止性条款） | 同上 |
| `quota` | 罚则/监管信息项（**不参与对租客合同的判定**） | 仅报告"依据附录" |

CLI 退出码判据按作用域取：`calc` 路径只校验 `scope in {calc, check}` 的条目 status。

### 4.2 第三态 `input_required`

"本不由规则包承载的外部输入"（如"当地市场租金水平"——规则包不承载、需运行时提供）标 `input_required`，**不阻断门控**，但判定层运行时显式索取，缺失即退出码 2，**绝不静默取 0/1**。

判别口诀：**"未核对"与"本不由规则包承载"是两回事**——前者挂 `pending` 拦门，后者挂 `input_required` 放行但运行时必索。

## 5. 义务类型与适用性（判定语义的根）

### 5.1 `effect` 分栏

法规里同一个门槛可能挂**性质完全不同**的义务，混在一个布尔里输出会把监管裁量说成企业的法定义务：

| effect | 含义 | 本项目实例 | 报告位置 |
|---|---|---|---|
| `standing_obligation` | 持续性义务（处理者无条件） | 押金一般不超过一个月租金 | 主结论栏 |
| `periodic_obligation` | 周期性义务 | 合同订立三十日内备案 | 主结论栏 |
| `conditional_institution` | **条件触发**（监管裁量权，非相对人无条件义务） | 政府可采取涨价申报/限定租金等价格干预 | **条件触发栏**（独立小节，不计入主结论） |

**频次/期限只取无条件义务栏**——条件触发项没有"多久一次"。

### 5.2 `applies_if` 与"不适用"的边界

本项目的关键适用性维度有两个：**主体（party）**与**房屋类型（lease_kind）**。

- 北京条例第三十六条的押金/租金上限，主体是**住房租赁企业**（含以自有住房从事住房租赁业务的企业）；**自然人之间**的租赁不适用。
- 民法典第七百零五条租期二十年上限，**无条件适用于任何租赁**。
- 上海条例第三十七条的保租房押金上限与租期下限，适用房屋类型是**保障性租赁住房**；普通租赁住房不适用（M1 新增维度）。

因此 `applies_if.party` 取值 `enterprise` / `any`；`applies_if.lease_kind` 取值 `affordable` / `ordinary`（`any` 表示不限）。合同主体非企业时，企业专属规则判 **`skipped`**；合同非保租房时，保租房专属规则同样判 **`skipped`**——两者都是**原文自带适用限制**（原文明确写了适用情形），符合"不适用只保留给原文明确写了例外情形的项"。

**反向陷阱防范**：`skipped` 绝不用于"缺材料"或"用户没做"。判别 = "这项义务有没有前提条件？"——原文是"应当 X"（无条件）→ 缺 X 记 `noncompliant`；原文自带主体/情形限制 → 才允许 `skipped`。

**第三个陷阱（M1 实测）**：**外部监管义务**（如"企业应自领取营业执照之日起三十日内备案"）在合同里**永远不会被载明**——执照领取日不是合同要素。此类规则对已知企业主体应判 `unknown`（"合同未载明，无法判定"），**不是** `skipped`（"不用做"）。把未观测记成不适用，等于替用户免除了他确实负有、只是合同查不到的义务。

### 5.3 `not_assessed` 与 `unknown`

- 若对某份合同**一条规则都不适用** → 整体等级 `not_assessed`（未评估），**绝不输出 `compliant`**。
- 合同未约定某要素（如未写租期）→ `unknown`（无法判定），原因是"未观测/未约定"，**不是**"符合"。

## 6. 合成数据纪律（引用 `data/README.md`）

测试样例一律合成合同：假姓名（"张三""李四"式样例名）、假手机号（`19900000000` 号段）、假身份证号。每个样例的植入真值显式登记在样例 JSON：`expect` / `also_expect`（规则判定真值）与 `expect_fields` / `expect_absent_fields`（要素抽取字段真值，B1 算字段级 P/R/F1 的独立来源）。详见 `data/README.md` §3。
