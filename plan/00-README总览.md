## 2. 决策记录（摘要）

完整决策记录见 `plan/06-决策记录与交付对标.md` §1（D1–D16）。

| # | 决策 | 备选方案 | 弃选理由 |
|---|---|---|---|
| D1 | 法规文本底座采用人大/政府官网静态直连源（最高法、北京人大、上海市政府、北京住建委） | 接入国家法律法规数据库 flk.npc.gov.cn 作底座 | flk 为 JS 渲染 SPA，程序化直连不可行（已实测，见 `data/README.md`）；官网静态源可实抓抽条，满足"原文逐字锚点"纪律 |
| D2 | 首期仅京/沪两城市差异包 | 首期覆盖全国多城市 | 各地条例素材未逐一查证，未核对原文不得落库（确定性纪律），故仅将已实抓抽条的京沪入包，其余列为扩展项 |
| D3 | 规则库做成 versioned ruleset（城市差异包机制） | 规则硬编码进引擎 | 城市差异是本题核心亮点；版本化使判定可复现、规则更新可追溯 |
| D4 | 离线交付：PySide6 桌面 exe + CLI 双入口 | Web 在线服务 | 隐私红线要求纯本地零上传；离线交付与"合同不上传"承诺一致 |
| D5 | 首期不使用 LLM（全链路确定性规则） | 接 LLM 做非结构化抽取兜底 | 纯确定性规则 + 结构化输入，正则可覆盖主要表述形态；零 LLM 则结论 100% 可复现、零 API 依赖、基准可离线跑 |
| D7 | 双重门控拆分（数值 status / 条款号 clause_status 两个独立状态） | 耦合成单一 status | 耦合会让条款号核不到时把已核对数值无谓阻断；或"悄悄当作已核对" |
| D9 | 义务类型分栏（standing / periodic / conditional_institution） | 混在一个布尔里输出 | "政府可以采取价格干预"是监管裁量权，混写会把裁量说成企业法定义务 |
| D10 | 判定状态五值（含 unknown / not_assessed） | 三态 | 三态无法区分"没看到"与"没检查过"，是判定类工具最易被攻击的假合规点 |

**诚实口径**：M0 未接远端、一次 CI 都没跑过，故 DoD 写"**本地等价校验**"并注明"未接远端，CI 待首推验证"。**未推送 = 未跑 CI**，M6 首推后据实补记真实 CI 结论与 run id。

**本地等价校验的完备形态（M0 已跑项清单）**：双解释器 pytest 全量 / 生成器 `--check` 逐字节 / 脱敏审计 `selftest` / 零字面量门禁 `--selftest` / CLI 全子命令退出码语义 / 骨架自检。**不可本机实跑的通路（CI 环境差异）显式标注"待首推验证"**——"等价"永远有缺口，写清楚等价物清单与缺口比笼统一句"本地等价校验通过"更诚实且可审计。
