# 03 - 判定引擎设计：统一中间表示、判定口径、模块详设

> 对应题面模块①③④。本文件定义"合同文本怎么进、判定怎么出、结论怎么表达"。

---

## 1. 全链路数据流

```
合同纯文本
   │  ① 条款切分（parser/clauses.py，规则优先）
   ▼
条款序列 [Clause(number, text, type, span)]
   │  ② 要素抽取（parser/extract.py，规则优先 + 槽位校验）
   ▼
合同卡片 LeaseCard（实体-属性-值-单位-证据）
   │  ③ 规则判定（engine/checker.py × 规则包）
   ▼
判定结果 [Finding(rule_id, status, reason, anchor)]
   │  ④ 报告渲染（report/sections.py 单一渲染源）
   ▼
人读 Markdown  +  机读 CSV/XLSX（逐字节可复现）
```

**设计要点**：① 与 ② 的产物都进**统一中间表示**（条款序列与合同卡片），后续"判定"就归约为"卡片字段 vs 规则条目"的结构化对齐。③ 只消费规则包与卡片，**不含任何政策数值字面量**（零字面量门禁扫描面）。④ 人读与机读**消费同一个章节结构函数**，使"两格式内容一致"成为结构性质而非人工比对。

## 2. 模块①：条款切分

### 2.1 输入输出

- 输入：合同纯文本（租客粘贴或导入）。
- 输出：`Clause` 序列，字段 `number`（条款号原文，如"第三条"）、`text`（条款正文）、`type`（类型标签）、`span`（在原文中的字符区间）、`located`（bool）。

### 2.2 切分策略（规则优先）

中文合同的条款号形态有限，按优先级枚举正则：

1. `第[一二三四五六七八九十百零〇\d]+条` （标准条号）
2. `^[一二三四五六七八九十]+、` （中文序号段落）
3. `^\d+[.、]` （阿拉伯数字段落）

**定位断言**：每个切出的 `number` 必须能在原文中定位到**逐字原文**（用 `text.find(number, cursor)` 且命中位置单调递增）。**无法定位的切分显式标注 `located=false` 并进"待人工确认"清单**，绝不静默吞掉（题面模块①确定性纪律）。

### 2.3 必防的工程陷阱（实测清单）

- **CRLF 残留**：入口统一 `\r\n` → `\n`，否则 `span` 计算与定位断言全错位。
- **伪空格**：从 PDF 复制的文本常有逐字符空格，切分前做"单字符间隔空格折叠"试探（仅当连续单字+空格占比超阈值时启用）。
- **全角/半角数字**：条款号 `第三条` 与 `第3条` 都收，但**保留原文形态**（不改写 `number`）。
- **中文路径与 GBK 控制台**：入口 `_ensure_utf8_stdio()`；文件读取显式 `encoding="utf-8"`，失败回落 `gb18030` 并在报告里记 `encoding_fallback`。

## 3. 模块③：要素抽取（合同卡片）

### 3.1 卡片结构

```python
@dataclass(frozen=True)
class Evidence:
    clause_number: str | None   # 条款号
    clause_text: str | None     # 条款原文片段（逐字）
    char_span: tuple[int, int] | None

@dataclass(frozen=True)
class Field:
    name: str            # 参数名，对应规则包 param
    value: object | None # 数值/字符串；None = 未观测
    unit: str | None
    confidence: str      # "high" | "low" | "absent"
    evidence: Evidence

@dataclass(frozen=True)
class LeaseCard:
    city: str | None
    party: str           # "enterprise" | "individual" | "unknown"
    fields: dict[str, Field]
    pending_manual: list[str]   # 待人工确认项
```

### 3.2 抽取口径

| param | 抽取来源 | 单位归一 | 未观测处置 |
|---|---|---|---|
| `lease_term_years` | "租赁期限…X 年" | 月→年（`/12` 两位小数） | `value=None` → `unknown` |
| `deposit_months` | "押金…X 个月租金" / 押金数额÷月租金 | 元→月（需月租金，缺失则 `input_required`） | `unknown` |
| `rent_prepay_months` | "一次收取…X 个月" / "押一付三"式 | 同 | `unknown` |
| `filing_days` | "订立之日起 X 日内备案" | 工作日/日分列 | `unknown` |
| `deposit_refund_days` | "返还住房后 X 个工作日内退还" | 同上 | `unknown` |
| `has_elements` | 民法典 704 条要素清单逐项命中 | — | 缺失项列入 `noncompliant` 明细 |

### 3.3 防幻觉三件套（本项目形态）

本项目**数值结论 100% 来自确定性规则**。要素抽取层：

1. **规则优先**：正则 + 槽位 + 合法性校验（数值超范围即丢弃，如租期 0 或 >100 年判 `low` 置信度）。
2. **要求原文逐字摘录**：`evidence.clause_text` 必须是合同原文的子串（`assert evidence.clause_text in raw_text`），不是子串即丢弃该字段。
3. **LLM 兜底（可选，默认关闭）**：见 §7。首期**不接 LLM**。

## 4. 判定语义（最易失分处，逐条定义）

### 4.1 判定状态五值

| status | 含义 | 触发条件 |
|---|---|---|
| `compliant` | 符合 | 数值满足规则 |
| `noncompliant` | 不符合 | 数值违反规则；**或**无条件义务要素缺失 |
| `skipped` | 不适用 | `applies_if` 不满足（原文自带适用限制） |
| `unknown` | 无法判定 | 该要素未观测/未约定 |
| `not_assessed` | 未评估 | **整体级**：一条规则都不适用 |

### 4.2 三条硬口径

1. **`skipped` 只给"原文明确写了适用情形"的项**。企业专属规则遇到自然人合同 → `skipped`（原文写了"住房租赁企业"这个主体限制）。**绝不**因为"合同里没写押金"就判 `skipped`——那是 `unknown`。
2. **无条件义务缺失 = `noncompliant`**。民法典 704 条"租赁合同的内容一般包括…"列出要素，合同缺失某项 → 记 `noncompliant`（要素不完整），**不记 `skipped`**。注意"一般包括"的措辞：报告中如实引用原文，判定理由写"要素缺失（建议补充）"，severity 记 `low`（非强制性措辞）。
3. **无适用项 → `not_assessed`，不输出 `compliant`**。"没查出问题"与"没检查过"必须可区分。

### 4.3 结论分栏（`effect`）

判定结果按 `effect` 分栏输出：`obligations`（无条件义务）与 `conditional_triggers`（条件触发/监管裁量）。**频次与期限只取无条件义务栏**。报告分节呈现，不合写。

## 5. 双重门控与作用域（引擎入口）

```python
def effective_ruleset(city: str, scope: str) -> Ruleset:
    """只返回 status=='verified' 且 scope 匹配的条目；缺失即 RulesetError。"""
```

- 门控**按作用域**取条目：`calc` 路径只校验 `scope in {"calc","check"}`。
- `status == "pending"` 的条目**绝不进判定路径**，但在产物里进"未启用清单"（显式可见）。
- `clause_status == "pending"` **不阻断**，只在"可证性"栏显示。
- `input_required` 标在字段层（卡片 `Field`），引擎运行时索取，缺失 → 退出码 2。

## 6. 报告（模块④）

### 6.1 单一渲染源

`report/sections.py` 的 `report_sections(result) -> list[Section]` 返回结构化章节；Markdown 渲染器与 XLSX 渲染器**各自读它**。于是"两格式内容一致"是结构性质，改一处两者同变。

### 6.2 必备章节

1. **输入事实**（合同主体、城市、抽取到的要素与证据条款号）
2. **参数来源块**（每项参数：发布机关 + 施行日期 + 文号 + URL + 抓取日期）——让读者不开仓库也能核证数值出处
3. **逐条判定**（判定状态 + 判定理由 + 规则 ID + 条款号锚点 + 法条原文逐字引用）
4. **条件触发栏**（`effect == conditional_institution`，独立小节）
5. **未启用清单**（`pending` 条目显式列出，"本次判定未启用以下规则"）
6. **待人工确认**（切分无法定位项）
7. **依据清单 + 免责声明**

### 6.3 溯源完整性硬约束

导出前断言：`溯源表行数 == 明细判定行数`，且每条引用的 `rule_id` 可在规则包中解析。不满足即**报错拒导**，不留"半溯源"报告。

### 6.4 机读产物字节确定性

- CSV：`open(..., newline="\n")`，无时间戳。
- XLSX：**自写最小 OOXML writer**（`ZIP_STORED` + 固定 `create_system=0` + 固定 `date_time=(1980,1,1,0,0,0)`），不引 openpyxl，保证"同输入逐字节一致"。
- **无外链**：报告内不得有 URL 外链关系项（URL 以文本形式出现在"参数来源块"是允许的——它是溯源内容，不是超链接）。断言 = XLSX 无 `External` 关系 + Markdown 无 `](http`。

### 6.5 免责声明（法律红线，题面 §6.1）

所有报告页面与导出文件**必须**携带："本报告为辅助参考的合同体检结果，不构成法律意见。"不得出现"律师审查""具有法律效力"等表述——由守门测试断言禁用词表。

## 7. LLM 使用决策

**首期不使用 LLM**（决策记录 D5）。理由：本项目判定是**纯确定性规则 + 结构化输入**，要素抽取用正则即可覆盖中文合同的主要表述形态；无 LLM 则结论 100% 可复现、零 API 依赖、基准可离线跑、脱敏面无外部调用。

**扩展项**：非结构化抽取兜底（罕见表述形态）可后续加 LLM 通路，纪律预先定死——LLM **只填"宁缺"槽位**，绝不覆盖确定性抽取值，绝不产生/修改任何 status 判定。

## 8. 包结构与分层

```
src/rca/
  __init__.py         # __version__、包入口
  cli.py              # CLI（唯一对外命令入口，_ensure_utf8_stdio）
  model.py            # LeaseCard / Finding / Result 数据类
  parser/
    clauses.py        # 条款切分
    extract.py        # 要素抽取
  engine/
    ruleset.py        # 规则包加载 + effective_ruleset 门控
    checker.py        # 判定引擎（零政策字面量）
    pipeline.py       # 编排层公开函数组（CLI 与 GUI 共用）
  report/
    sections.py       # 单一渲染源
    markdown.py       # 人读渲染
    ooxml.py          # 自写最小 XLSX writer
  knowledge/          # 规则包/快照定位（find_data_dir 冻结分支）
  packaging.py        # 打包白名单 build_datas（包内，避免遮蔽 PyPI packaging）
tools/
  fetch_sources.py    # 官方快照抓取 + --check
  gen_rulesets.py     # 规则包生成器 + --check
  gen_samples.py      # 合成合同样例生成器 + --check
  audit_desensitize.py# 脱敏审计（selftest/tracked/history/messages 四模式）
  check_literals.py   # 零政策字面量门禁（token 从规则包实算）
  verify_package.py   # 冻结态验收
  build_release.py    # Release zip 打包（确定性）
```

**分层纪律**：`engine/` 与 `report/` 不得 import GUI；`gui/` 只经 `pipeline.py` 公开函数取数（AST 静态门禁守）。辅助模块 `packaging.py` **放包内不放顶层**（避免遮蔽 PyPI `packaging`，PyInstaller 依赖它）。

## 9. CLI 契约（退出码语义，定稿后锁进测试）

| 退出码 | 语义 |
|---|---|
| 0 | 完成（无论是否检出不符合） |
| 1 | 检出 `noncompliant`（判定类工具的既定语义） |
| 2 | 输入不可用 / 用法错误 / 参数错误 / `input_required` 缺失 |
| 3 | 缺可选依赖（如 GUI 的 PySide6） |

**注意**：`1` 不是失败，是"检出不符合"的既定语义；**"没判定"（2）与"判出不符合"（1）是两种不同的退出码语义**，混在一起会让 CI 误判。

子命令：`check`（单件体检）/ `scan`（批量）/ `report`（导出）/ `rules`（规则包查看）/ `bench`（基准）/ `gui`（惰性导入）/ `selftest`（冻结态自检）。
